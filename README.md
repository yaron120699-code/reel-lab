# מעבדת מתחרים · בדרך

כלי מחקר מקומי לניתוח מבני של רילים של יוצרים אחרים.

**העיקרון: לשאול מבנה, אף פעם לא זהות.**

הכלי מפרק ריל לשדות מבניים — הוק, הבטחה, לולאות פתוחות, אסקלציה, פייאוף — ומסמן כל שדה
כ**נמדד**, **נצפה** או **מוסק**. הוא לא מייצר תוכן, לא מציע לחקות ניסוח או פרסונה, ולא ממציא
מספרים שלא היו בייבוא.

---

## מה הכלי עושה בהרצה הזו

1. הוספת יוצר למעבדה.
2. ייבוא תוצאת Apify (JSON) וצירוף קובץ MP4.
3. שמירת הריל, התמלול, המדדים הציבוריים והמקור.
4. ספריית רילים עם סינון.
5. ניתוח מבני מובנה לריל.
6. השוואה בין שני רילים, עם בדיקת השוואתיות.
7. שמירת תבנית (Pattern Card) עם הראיות שלה.

מה שלא נבנה בכוונה: הרשאות, חיוב, צוותים, תזמון, פרסום, Idea Lab, סקרייפינג אוטומטי של פרופילים.

## הפעלה מהירה

דרישות: Node.js 20 ומעלה, npm.

```bash
npm install
cp .env.example .env
npm run db:migrate
npm run dev
```

הכלי עולה על <http://localhost:3000> ומפנה לעמוד היוצרים.

> **אם `npm install` מנסה לקמפל את `better-sqlite3` ונכשל** — החבילה כבר כוללת קבצים בנויים
> מראש לכל הפלטפורמות הנפוצות, ו-npm מנסה לבנות מחדש בלי צורך. במקרה כזה:
> ```bash
> npm install --ignore-scripts
> ```
> זה מספיק, ואין צורך בכלי קומפילציה מותקנים.

### טעינת נתוני דמו

הדרך המהירה לראות את כל הזרימה בלי שום חיבור חיצוני:

```bash
npm run seed:demo
```

או מהממשק: עמוד **יוצרים** ← **טעינת נתוני דמו**.

הדמו טוען יוצר לדוגמה, שישה רילים, שני ניתוחי דוגמה מסומנים, וקובצי MP4 קטנים שנוצרים מקומית
באמצעות ffmpeg. אם ffmpeg לא מותקן — כל השאר עובד, ורק צירוף הווידאו האוטומטי מדולג.
אפשר להריץ שוב: הנתונים מתרעננים ולא מוכפלים.

## משתני סביבה

מעתיקים את `.env.example` ל-`.env`. כל הערכים בקובץ הדוגמה הם placeholders, והאפליקציה
עולה ובונה כמו שהיא.

| משתנה | ברירת מחדל | תיאור |
| --- | --- | --- |
| `DEMO_MODE` | `true` | מצב דמו — כל הזרימה עובדת בלי אישורים חיצוניים |
| `DATABASE_FILE` | `./data/app.db` | קובץ ה-SQLite המקומי |
| `POSTGRES_URL` | ריק | חיבור Supabase בענן; כשמוגדר הוא מחליף אוטומטית את SQLite |
| `LAB_USERNAME` | ריק | שם משתמש פרטי למעבדה ב-Vercel |
| `LAB_PASSWORD` | ריק | סיסמת גישה פרטית למעבדה ב-Vercel |
| `STORAGE_DIR` | `./data/uploads` | תיקיית קובצי הווידאו |
| `ANALYSIS_PROVIDER` | `fixture` | `fixture` (אופליין) או `anthropic` (ניתוח חי) |
| `ANALYSIS_API_KEY` | ריק | נקרא רק כש-`ANALYSIS_PROVIDER` אינו `fixture` |
| `ANALYSIS_MODEL` | `claude-sonnet-4-5` | שם המודל לניתוח חי |
| `APIFY_API_TOKEN` | ריק | אופציונלי. הייבוא הידני עובד בלעדיו |

### על הסודות

`APIFY_API_TOKEN` ו-`ANALYSIS_API_KEY` נקראים אך ורק בצד השרת, כל אחד במודול יחיד
(`src/lib/apify/client.ts`, `src/lib/analysis/providers/anthropic.ts`). הם לא מגיעים לדפדפן,
לא נכתבים ללוגים, ולא מופיעים ב-UI. הממשק מקבל דגלים בוליאניים בלבד
(`publicRuntimeFlags`) שאומרים אם משהו מוגדר — לא מה הערך שלו. שגיאות רשת מהקריאות האלה
נבלעות בכוונה ולא מועברות הלאה, כי אובייקט שגיאה של `fetch` יכול לשאת את כותרות הבקשה,
והכותרות נושאות את המפתח.

`.env` מוחרג מ-git. גם `data/` — בסיס הנתונים והסרטונים — מוחרג.

### Supabase ב-Vercel

חיבור Supabase דרך Vercel Storage יוצר אוטומטית `POSTGRES_URL`. כשמשתנה זה קיים,
האפליקציה משתמשת ב-Postgres; במחשב המקומי, ללא המשתנה, היא ממשיכה להשתמש באותו SQLite.
הסכמה נוצרת אוטומטית ובאופן idempotent בבקשה הראשונה.

כדי להעביר פעם אחת את הנתונים המקומיים הקיימים לענן:

```bash
npx vercel link
npx vercel env pull .env.cloud.local --environment=production
npm run db:migrate:cloud
```

ההעברה בטוחה להרצה חוזרת ומעדכנת רשומות לפי המזהה שלהן. רשומות MP4 אינן מועברות, כי
הקבצים עצמם נמצאים רק בתיקייה המקומית; ייבוא וניתוח רילים מכתובת עובדים בענן ללא MP4.

ב-Vercel חובה להגדיר גם `LAB_USERNAME` ו-`LAB_PASSWORD`. בלי שניהם הפריסה נסגרת עם 503;
כשהם מוגדרים, הדפדפן מבקש אותם לפני כל גישה למעבדה ולנתיבי השרת שלה.

## ייבוא: איך זה עובד

### הזרימה הראשית — ידנית

1. מריצים את האקטור ב-Apify ומעתיקים את ה-JSON של התוצאה.
2. בעמוד **ייבוא ריל**: בוחרים יוצר, מדביקים את ה-JSON, מייבאים.
3. מורידים את ה-MP4 בנפרד ומצרפים אותו לריל.

ה-JSON מתקבל בשלוש צורות: פריט בודד, מערך פריטים, או אובייקט עם `items`.

השדות שמנורמלים: `url`, `shortCode`, `caption`, `timestamp`, `videoDuration`,
`videoPlayCount`, `likesCount`, `commentsCount`, `transcript`, `videoUrl`, `displayUrl`,
`ownerUsername`. יש גם נפילה אחורה לשמות נפוצים אחרים (`videoViewCount`, `playCount`,
`takenAtTimestamp`, `duration`, `shortcode`).

**שדה שחסר בייבוא נשאר `null` — הוא לא הופך לאפס.** לצד כל ערך נשמר שם השדה שממנו הוא הגיע,
כדי שבניתוח אפשר יהיה לסמן אותו כנמדד ולהצביע על המקור. ה-JSON המקורי נשמר כפי שהוא לצד הריל.

### משיכה ישירה מ-Apify (אופציונלי)

אם `APIFY_API_TOKEN` מוגדר, אפשר למשוך dataset לפי מזהה מעמוד הייבוא. זו נוחות בלבד —
הזרימה הידנית היא הנתמכת, והיא לא תלויה בטוקן.

## חוזה הראיות

כל שדה בניתוח נושא סיווג אחד בדיוק, והסכמה אוכפת אותו:

| סיווג | פירוש | חובה | אסור |
| --- | --- | --- | --- |
| **נמדד** | קיים בנתונים או בקובץ שיובאו | `sourceField` | `confidence` |
| **נצפה** | נראה או נשמע ישירות בריל | — | `sourceField`, `confidence` |
| **מוסק** | פרשנות או השערה של מודל | `confidence` | `sourceField` |

**שימור צופים מסומן תמיד כמוסק.** הסכמה פשוט מסרבת לשמור אותו אחרת. לנתונים הציבוריים של
אינסטגרם אין עקומת צפייה, ולכן טענה על שימור של יוצר אחר יכולה להיות רק היפותזה.

מעל כל ניתוח מוצג **מד הראיות** — פס שמראה כמה מהשדות נמדדו, כמה נצפו וכמה מוסקים. זו התשובה
המהירה לשאלה "כמה מזה בכלל ניחוש".

צבע בממשק הזה אומר דבר אחד בלבד: סטטוס ראיה. ירוק נמדד, כחול נצפה, אוקר מוסק. שום דבר אחר
לא צבוע.

## ניתוח

ברירת המחדל היא ספק `fixture`: ניתוחי דוגמה מוכנים מראש לשני רילים של הדמו, מסומנים בכל מקום
שהם מופיעים בו. **הכלי לא ימציא ניתוח לריל שלא ראה** — ספק ה-fixture מסרב במפורש ומסביר מה
להגדיר.

### ניתוח חי עם Gemini

```bash
ANALYSIS_PROVIDER=gemini
ANALYSIS_API_KEY=<מפתח מ-Google AI Studio>
ANALYSIS_MODEL=gemini-3.5-flash-lite
```

`gemini-3.5-flash-lite` הוא המודל המוגדר בהרצה הנוכחית. המפתח נקרא בצד השרת בלבד, נשלח אך ורק בכותרת
`x-goog-api-key`, ולעולם לא ב-URL — כתובות נשמרות בלוגים של פרוקסי ובהיסטוריית דפדפן.

**מגבלה חשובה: קובץ ה-MP4 לא נשלח ל-Gemini.** הניתוח רץ על הכיתוב, התמלול והמדדים הציבוריים
בלבד. לכן המודל מקבל הוראה מפורשת לא לתאר שום דבר שאפשר לדעת רק מצפייה — חיתוכים, מסגור,
תנועות מצלמה, טקסט על המסך — ולסמן את `visualHook` כמוסק בוודאות נמוכה, עם ציון שהסרטון לא
היה זמין. תיאור ויזואלי ממודל שלא ראה פריימים הוא המצאה, והוא מסוכן במיוחד כי הוא נכנס
למעבדה עם תווית "נצפה".

### ניתוח חי עם Anthropic

```bash
ANALYSIS_PROVIDER=anthropic
ANALYSIS_API_KEY=…
ANALYSIS_MODEL=claude-sonnet-4-5
```

### מה קורה כשמשהו נכשל

שגיאות רשת, הרשאה, מכסה, JSON פגום או אי־עמידה בסכמה הופכות כולן להודעה בעברית בממשק.
**גוף התשובה של הספק לא מוצג לעולם** — הוא עלול להכיל הד של הבקשה, והבקשה נושאת את המפתח.
תשובה שלא עוברת ולידציה מול הסכמה נזרקת ולא נשמרת. אין שמירה חלקית ואין השלמה של שדות חסרים.

הניתוח מופעל ידנית בכפתור **"הרצת ניתוח"** בדף הריל. אין הרצה אוטומטית אחרי ייבוא — קריאה
לספק חיצוני נשארת החלטה מפורשת שלכם.

הגבול בין הכלי לספק הניתוח נמצא ב-`src/lib/analysis/provider.ts`. החלפת ספק = מודול אחד נוסף
תחת `providers/` וענף אחד בפונקציית הבחירה. כרגע קיימים שלושה: `fixture.ts`, `gemini.ts`
ו-`anthropic.ts`, וכולם חולקים את אותו פרומפט, אותה סכמה ואותו חוזה ראיות.

לכל ניתוח נשמרים: `promptVersion`, `transcriptRef`, `language`, ספק, מודל, מצב הרצה
(`live` / `fixture`) וחותמת זמן.

## השוואה

לפני ההשוואה עצמה מוצגת **פאנל השוואתיות** עם שש בדיקות: אותו יוצר, תקופת פרסום דומה, נושא
דומה, פורמט דומה, ספירת צפיות לשניהם, וסיכון למבלבל עונתי או תזמוני. שלוש אי־התאמות ומעלה
מסמנות את ההשוואה כלא בטוחה, והממשק מציג אזהרה במקום מסקנה.

**מדד ביצועים יחסי ליוצר**: ספירת הצפיות של הריל חלקי חציון הצפיות של רילים אחרים של אותו
יוצר. מספרים מוחלטים בין יוצרים שונים מספרים על גודל קהל, לא על איכות — ולכן המדד תמיד
יחסי ליוצר. אם אין קוהורט של שלושה רילים לפחות, המדד מסרב להחזיר מספר. אם אין צפיות והחישוב
נופל ללייקים, הוא מסומן כוודאות נמוכה.

הכלי לא גוזר סיבתיות. גם כשכל הבדיקות תואמות, שני מבנים והפרש ביצועים הופיעו יחד — זה לא
אומר שהאחד גרם לשני.

## תבניות (Pattern Cards)

תבנית היא המקום היחיד שבו ממצא הופך להמלצה, ולכן היא נושאת את הראיות שלה: רילים תומכים,
מה סותר, ספירת ראיות, ודאות, תרגום לבדרך, והערת "לא להעתיק".

- **ספירת הראיות נגזרת, לא מוזנת.** רק ריל שקיים ושיש לו ניתוח שמור נספר.
- **ודאות גבוהה דורשת שלושה רילים מנותחים לפחות.** בקשה לוודאות גבוהה עם פחות מזה מורדת
  אוטומטית, והממשק אומר שזה מה שקרה.
- תבנית בלי אף ריל מנותח נדחית.

### שכבת ההחלפה ל-Supabase

`src/lib/repositories/types.ts` מגדיר את הממשקים. `sqlite.ts` ו-`postgres.ts` מממשים אותם.
`index.ts` הוא המפעל היחיד ובוחר לפי קיום `POSTGRES_URL`. אף עמוד, רכיב או שירות לא מייבא
דרייבר בסיס נתונים ישירות.

אותו דבר לאחסון: `MediaStorage` ב-`src/lib/storage/index.ts` הוא הממשק, והמימוש המקומי
כותב ל-`data/uploads`.

### הערה על Prisma

הבקשה המקורית ציינה Prisma. הסביבה שבה נבנה הפרויקט חוסמת את `binaries.prisma.sh`, ולכן
Prisma לא הצליח להתקין את מנועי ה-engine ולא היה אפשר להריץ `prisma generate` — מה שאומר
שלא היה אפשר לאמת בילד, טיפוסים או בדיקות. במקום זה נבנתה שכבת `better-sqlite3` מאחורי
ממשקי ה-repository שמתוארים למעלה. הסכמה עצמה (`src/lib/db/schema.ts`) מתורגמת אחד־לאחד
לטבלאות, ומעבר ל-Prisma בהמשך הוא מימוש נוסף של אותם ממשקים.

## פריסה ל-Vercel (מצב תצוגה)

אפשר לפרוס את הכלי ל-Vercel כדי להראות אותו, אבל חשוב להבין מה זה כן ומה זה לא.

הגדרות סביבה ב-Vercel:

```
DEMO_MODE=true
DATABASE_FILE=/tmp/app.db
ANALYSIS_PROVIDER=fixture
```

### למה זה עובד ככה

ב-Vercel כל פונקציה serverless מקבלת `/tmp` משלה, והוא נמחק כשהמופע ממוחזר. כלומר הפונקציה
שמרנדרת את `/reels` והפונקציה שמרנדרת את `/reels/[id]` עובדות על שני קובצי SQLite שונים
לגמרי. עם מזהים אקראיים, הקישור שנוצר באחת פשוט לא קיים בשנייה — ומכאן ה-404.

הפתרון: **מזהים קבועים בקוד**. כל השורות של הדמו — היוצר, ששת הרילים, המדדים, הניתוחים,
ההשוואה והתבנית — נושאות מזהים מקובעים ב-`src/lib/demo/fixtures.ts`. כשמתקיים
`DEMO_MODE=true` ו-`VERCEL=1`, כל פונקציה בונה לעצמה את אותו מערך נתונים בדיוק לפני שהיא
קוראת משהו. הזריעה אידמפוטנטית ונשמרת במטמון לכל תהליך, כך שמופע חם משלם עליה פעם אחת.

הכפתור הידני "טעינת נתוני דמו" והזריעה האוטומטית משתמשים באותו seeder בדיוק
(`src/lib/demo/seed.ts`), כך שיש רק מערך נתוני דמו אחד לתחזק.

### מגבלות שנשארו ב-Vercel

- **שום דבר לא נשמר.** יוצר שתוסיפו, ריל שתייבאו או תבנית שתשמרו ייעלמו כשהמופע ימוחזר.
  הבאנר בראש העמוד אומר את זה במפורש.
- **אין קובצי וידאו.** האחסון המקומי לא שורד, ולכן הזריעה ב-Vercel מדלגת על יצירת MP4.
  נגן הווידאו בעמוד הריל יראה שאין מדיה מקומית.
- **העלאת MP4 לא תעבוד בפועל.** אפשר להעלות, אבל הקובץ ייעלם.
- **שתי לשוניות עשויות לפגוש מופעים שונים.** מכיוון שכל המופעים בונים נתונים זהים, זה לא
  נראה, אבל כל שינוי שתעשו קיים רק במופע אחד.
- **זה לא מצב עבודה.** למחקר אמיתי הריצו מקומית, שם ה-SQLite והקבצים נשמרים.

הצעד הקבוע — Supabase או בסיס נתונים מנוהל אחר — לא נכלל בשינוי הזה.
